# Integrated source security review

Pinned source `baf31877c01e525b610a87830bb0165376ab16e3`. All **279** FastAPI application routes are enumerated in `route-inventory.json` and the readable route matrix. Generated OpenAPI/docs framework routes are not application feature endpoints. This is a source/dependency review and focused isolated verification, not a live penetration test.

| Surface | Verified source behavior | Required before live exposure |
|---|---|---|
| Service authentication | Protected routers include service-token dependency. Bound mode checks signed tenant/role/expiry tokens. Legacy mode can bypass principal/RBAC checks. | Require bound mode in deployment profile; no shared browser service token; test role matrix. |
| Human sessions | Separate opt-in OIDC router; secure session cookie, local hashed session storage, CSRF on logout/revoke. Other API routes depend on Bearer service principals. | Reviewed session-to-principal integration and real authorized two-tenant tests; no assumption cookie login grants API access. |
| Persistent writes | Legacy engagement/support/advisory handlers can write when `SCEC_PERSISTENCE_ENABLED=1`, dedicated PostgreSQL namespace and allowlist configured. Manifest booleans are not a global write firewall. | Keep persistence=0, DB URL absent and write routes unproxied; real DB transaction/idempotency/recovery evidence before later activation. |
| Preview functions | Later modules use per-module staging flags, bound tenant roles and synthetic contracts; mutation-shaped blocked routes return 503. Some older intake contracts accept personal fields for validation even though they do not persist. | Exact route allowlist, synthetic-only inputs, minimization; do not expose every POST because most are previews. |
| CSRF/origin | Human logout/revoke validate CSRF; service-token APIs do not authenticate through browser cookies. Embeds have route-specific origin/header controls. | Browser session authorization changes must bring CSRF to every cookie-authenticated mutation. Verify actual proxy/cookie behavior. |
| Rate/request limits | Field/list bounds exist in many models; no global request-body byte cap or rate-limit middleware found. | Reviewed proxy/application limits plus executable tests; do not claim global protections from model bounds. |
| CORS/CSP | No general permissive CORS middleware found; embed-specific policy is narrow. Existing frontend CSP forbids network connections, forms and framing. | Reviewed same-origin endpoint integration and narrowly scoped CSP changes; preserve other apps/protected pages. |
| Recipients/transports/jobs | Modern newsletter/campaign modules produce synthetic previews and retain outbound/subscriber/scheduling/publication prohibitions. Legacy canonical contacts include email/consent fields. No live transport or scheduler certification supplied. | Do not implement/activate adapters, real recipients, subscribers or jobs as a readiness shortcut; independent Stage 2 approval/evidence. |
| Deletion/federation | Preview/blocked endpoints and false safety contracts do not authorize real deletion or federation. | Keep disabled. Privacy and independent activation approvals required. |
| Packaging/proxy | Frontend Compose reuses the live v8.7 container name and port; no backend Docker deployment exists in this architecture. | Never run the candidate's Compose against the live project. Use approved separate immutable source + venv/systemd and reviewed proxy diff. |

Minimal proposed remediation backlog (no implementation or feature development in this audit): session/principal bridge preserving tenant/RBAC/CSRF; explicit production bound/read-only profile and route allowlist; request-size/rate protections; correct existing Feedback launcher destination; verified Release Console product/repository/runtime mapping; privacy enforcement/rights/suppression implementation only after policy approval. Each requires a narrow review PR and focused tests before main/deployment. Main's old historic checksum file is not the merged-source manifest: three comment-only Python differences and a new Docker ignore file are recorded by the new external manifest.
