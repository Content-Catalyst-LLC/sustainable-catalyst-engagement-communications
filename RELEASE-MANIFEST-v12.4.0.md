# v12.4.0 — Editorial workflow and separation of duties

Verified predecessor v12.3.0: `8a58c703ac5d9d48373e90aada75f891c71074cd`.

Existing-service `/v1/editorial-workflows/status` and POST `/preview` are default-off under `SCEC_WORKFLOWS_STAGING_ENABLED=0`, bound to existing service identity, allowlisted tenant and administrator role. Every dangerous flag denies access; all seven production gates remain pending. No human authentication or real identity/role system is introduced.

Frozen synthetic review-decision records contain opaque decision reference, synthetic reviewer UUID, one editorial/scientific/legal/privacy role, approve/reject/abstain outcome, exact subject hash/revision, explicit decision time and bounded reason code. Canonical record hashes are recomputed; ordinary field mutation, hash tampering, arbitrary comments/PII and conflicting outcome/reason declarations are rejected. Records are fixture values, not database entries, signatures or real reviewer attestations.

A workflow binds the actual v12.3 policy envelope and uses exactly its evaluation clock, preventing stale policy timing from being silently reused. One decision per role is admitted. All four roles must have current approvals by distinct reviewers, none equal to the synthetic author. Missing roles, self-approval, role collisions, stale subject hash/revision, future decisions or decisions before the source revision invalidate completion and withhold all variations. Invalid decision declarations remain visible in bounded simulation evidence rather than granting approval. Duplicate roles/decision IDs and cross-tenant fixtures reject the contract.

A revised policy invalidates old decisions; caller fixtures preserve those records for audit and can submit a new review set separately. The simulation does not update or delete historical records. Even a complete review set cannot override source policy denial. Review-complete-preview means only fixture eligibility; verified identities/roles, live approval, changed roles, delivery authorization, publication, persistence and production certification remain false.

The existing persistent advisory approval workflow already disallows requester self-approval, but is intentionally not invoked here because it changes database state and can activate engagements. This module preserves that system and implements only the separately specified synthetic review contract, reusing shared scope, frozen fixture, source-policy and time validation interfaces. No credentials, production records, dependencies, frontend, WordPress, migrations or database changed. Live approve/change-role/commit/send/publish/activate/delete/federate routes remain503. See deployment/V1240-DEPLOY.md. Full Mac/Contabo, preflight, protected16/source/archive checks and exact-commit loopback/shutdown gates must close before v12.5.
